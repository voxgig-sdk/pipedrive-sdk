Channel

Operations

Every route this entity exposes. Each route links to its own reference on this page.

Method Route SDK operation Returns
POST /channels create The channel registered
POST /channels/messages/receive create The message was registered in the conversation
DELETE /channels/{channel-id}/conversations/{conversation-id} remove The conversation was deleted
DELETE /channels/{id} remove The channel was deleted

create

POST /channels

Operation ID: addChannel.

Authentication: API key in the header (api_key) or oauth2 (oauth2).

Request body

application/json

Property Type Required Description
avatar_url string (url) No The URL for an icon that represents your channel
name string Yes The name of the channel
provider_channel_id string Yes The channel ID
provider_type enum: facebook, whatsapp, other No It controls the icons (like the icon next to the conversation)
template_support boolean No If true, enables templates logic on UI. Requires getTemplates endpoint implemented. Find out more here.

200: The channel registered

POST /channels/messages/receive

Operation ID: receiveMessage.

Authentication: API key in the header (api_key) or oauth2 (oauth2).

Request body

application/json

Property Type Required Description
attachments array of object No The list of attachments available in the message
attachments[].id string Yes The ID of the attachment
attachments[].link_expires boolean No If true, it will use the getMessageById endpoint for fetching updated attachment's urls. Find out more here
attachments[].name string No The name of the attachment
attachments[].preview_url string No A URL to a preview picture of the file
attachments[].size number No The size of the attachment
attachments[].type string Yes The mime-type of the attachment
attachments[].url string Yes A URL to the file
channel_id string Yes The channel ID as in the provider
conversation_id string Yes The ID of the conversation
conversation_link string (url) No A URL that can open the conversation in the provider's side
created_at string (date-time) Yes The date and time when the message was created in the provider, in UTC. Format: YYYY-MM-DD HH:MM
id string Yes The ID of the message
message string Yes The body of the message
reply_by string (date-time) No The date and time when the message can no longer receive a reply, in UTC. Format: YYYY-MM-DD HH:MM
sender_id string Yes The ID of the provider's user that sent the message
status enum: sent, delivered, read, failed Yes The status of the message
